## 왜 불만족스러운가 (진단)

1. **연습 단위가 글자 한 개로 줄었다.** `>`와 공백을 상자 두 개에 넣고 Enter, `**`를 네 상자에 넣고 Enter. 한 판(5문제)이 1~2분에 끝나고, 공백 문자용 상자까지 따로 있다. 원래 제품이 겨냥한 문제("10분이면 이해하지만 손에 붙는 데는 몇 달")에 이 드릴은 닿지 않는다 — 문서를 쓰는 행동이 사라졌기 때문이다. 오답 1회에 정답 전체가 바로 펼쳐지므로 회상 연습도 아니다.
2. **Level 1을 끝내면 갈 곳이 없다.** Summary의 다음 행동은 "Practice again"(같은 12개 요소 반복) 아니면 "Change level"(둘 다 Coming soon). 첫 화면에서 세 레벨 중 둘이 "COMING SOON"이라 첫인상이 "미완성"이다. 두 달 넘게 그 상태다.
3. **디자인이 Jiwon의 현재 취향·사이트와 어긋난다.** 크림색 종이 질감, 책 펼침면과 책등, 페이지 넘김, 세리프 헤드라인, 타자기처럼 한 글자씩 찍히는 "Why bother" 문구. intend.md에 적힌 기준(흰 바탕, Mintlify·Todoist 느낌, 설명하지 말고 보여주기, 스크롤마다 바뀌는 움직임 금지, 톺키·Wonboard 페이지가 본)과 전부 반대다. 허브의 흰 제품 페이지 안에 크림색 책 캡처가 들어앉은 장면에서 그 간극이 한눈에 보인다. 휴대폰에서는 첫 화면에 헤드라인과 본문만 보이고 시작 단추가 접힌 아래에 있다.
4. **콘텐츠 하나 늘리는 공정이 너무 무겁다.** 문법 요소 하나(예: thematic-break)가 비테스트 파일 11개 + 배치 생성·검증·봉인 스크립트에 걸친다. 배치 31개마다 generate/check/publish 스크립트 세 벌, 리뷰어 2명 digest, provenance 게이트. 심사위원에게 증거를 보이기 위한 Build Week 공정이 지금은 L2·L3가 열리지 못한 이유다.
5. **쓰는 사람이 없고, 있는지 알 방법도 없다.** 피드백 0건, 저장소 조회 3회, 계측 없음. Build Week 관객이 빠진 뒤 유입 경로가 없다. 영어 전용이라 Jiwon의 주 관객(한국어 사용자)에게도 닿지 않는다 — 7월 계획서의 "What's next"가 이미 "Korean first"였다.
6. **작은 어긋남들.** 항상 도는 타이머(7/19 교육학 리뷰가 "압박 없는 학습" 철학과 충돌한다고 지적, 아직 그대로), 단추 이름이 키 이름("Enter ↵"), 왼쪽 면의 예시가 늘 단어 "Example", 3레벨 구조가 코드에서 "chapter/level/entry" 세 이름으로 불림.

## 방향 선택지

**A. 지금 틀 유지 + L2·L3 채우기.** 13개 요소를 현재 공정으로 구현한다. 비용이 크고, 끝나도 "글자 상자 드릴"이라는 핵심 불만은 그대로다. 추천하지 않는다.

**B. 다시 정의하고 다시 짓는다 (추천).** 엔진·문제은행·배포는 살리고, 연습 단위를 "기호 한 글자"에서 "짧은 실제 문서 한 장"으로 되돌린다. 렌더된 목표 문서를 보고 진짜 에디터에 마크다운을 쓰면 구조로 채점한다(엔진은 이미 이걸 한다). 한국어 우선, 흰 바탕, 톺키·Wonboard 제품 페이지와 같은 결, 책 메타포·페이지 넘김·타이머·레벨 잠금 제거. 진도는 가볍게 localStorage에 "배운 기호 지도"로(세션 저장소만 쓰는 D7 정책은 이미 #41·피드백 저장소로 한 번 뒤집혔다). 잠자는 L3~L5 콘텐츠는 "AI에게 주는 지시문 쓰기" 트랙으로 되살린다 — Jiwon의 원래 문장 "Markdown is the first code you write with AI"와 맞는 자리다. 계측(허브와 같은 동의 기반 Cloudflare Web Analytics)을 첫 PR에 넣어 다음 판단은 숫자로 한다.
  규모: 리포지셔닝 + 화면 재설계라 작은 PR 묶음이 아니라 계획서 한 장(명세 → 서로 다른 시안 2~3개를 실제 화면으로 → Jiwon 선택 → 무인 구현)으로 간다. 첫 덩어리는 "Level 1을 새 화면으로 다시 짓기"(한국어 UI, 문서 단위 연습, 10~12개 기호, 진도 지도)이고, "AI 지시문" 트랙은 그다음이다.

**C. 정리하고 보류.** README·허브 문구를 지금 제품에 맞게 고치고(세 이야기를 하나로), 새 투자는 멈춘다. 사용자 0, 유입 경로 없음이라는 사실 앞에서 합리적인 선택이다. 다른 제품(Wondrop·톺키)에 시간을 쓰는 편이 낫다고 판단되면 이쪽이다.

솔직한 단서: "먼저 계측만 붙이고 한 달 보자"는 보통 좋은 순서지만, 지금은 유입 경로가 없어서 한 달을 재도 0이 나온다. 그래서 이 결정은 데이터가 아니라 "이 제품이 존재하길 원하는가"로 정해진다. 원한다면 B, 아니면 C다.

## Jiwon이 정할 것

1. 방향: B / C (A는 비추천).
2. B라면 — 한국어 우선이 맞는가(영어는 그 뒤).
3. B라면 — 진도를 브라우저에 남기는 것(localStorage, 로그인 없음)을 허용하는가.
4. B라면 — 디자인 기준을 intend.md의 제품 페이지 기준(흰 바탕, 톺키·Wonboard 결)으로 잡아도 되는가, 아니면 nabimd만의 다른 방향을 원하는가.

결정이 오면 command-discipline으로 무인 실행용 계획서를 쓴다. 이 세션 워크트리에서 nabimd를 고칠 때는 메모리의 형제 저장소 워크트리 절차를 따른다.
